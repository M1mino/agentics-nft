## 2. ПОТОК ПОЛЬЗОВАТЕЛЯ

### Первый вход (нет NFT)
```
Пользователь → @AgenticsBot
                   ↓
  "Привет! У тебя ещё нет Agentics-агента.
   Купи NFT на GetGems,
   потом зайди в приложение чтобы активировать."
                   ↓
         ┌─── [Кнопка: 🛒 Купить на GetGems]
         └─── [Кнопка: 🚀 Открыть Mini App]
```

### Верификация (Mini App)
```
Пользователь → Mini App (через WebApp кнопку)
                   ↓
       Подключает кошелёк (TON Connect)
                   ↓
       Mini App проверяет NFT коллекции Agentics
                  /           \
           Есть NFT           Нет NFT
              ↓                   ↓
       Выбирает агента →   "Купи на GetGems"
       Вводит API-ключ
       (OpenAI / DeepSeek)
              ↓
       Mini App выдаёт TOKEN
       (sha256(tg_id + nft_id + secret))
       + ссылка: "Вернись в бота и введи код"
              ↓
       tg_id → { nft_id, api_key, agent, provider }
```

### Активация в боте
```
Пользователь → @AgenticsBot → /start [TOKEN]
                   ↓
       Проверяю TOKEN → расшифровываю
       Сохраняю в базу:
       tg_id → { nft_id, api_key, agent, provider, activated_at }
              ↓
       "Агент активирован! Теперь ты — Mentor-01.
        Задавай любой вопрос."
```

### Диалог
```
Пользователь → @AgenticsBot → "Привет!"
                   ↓
       Проверка: есть ли tg_id в базе?
              /           \
          НЕТ             ЕСТЬ
            ↓                ↓
     отправляю на      Загружаю системный промпт агента
     Mini App          Беру API-ключ пользователя
```

## 4. ЛОГИКА ПРОВЕРКИ NFT

### Подход: событийный (event-driven) вместо поллинга

Вместо проверять ВСЕХ пользователей каждые N минут —
отслеживаем транзакции КОНКРЕТНЫХ NFT,
которые уже активированы в боте.

### Как работает:

```
База активированных NFT:
  [nft_address_1] → [tg_id_1]
  [nft_address_2] → [tg_id_2]
  ...

Фоновый процесс каждые 2-3 минуты:
  GET /api/v3/nft/transfers?
    collection_address=EQC_..._RS_k
    &limit=50
    &start_lt={последняя_известная}
    
  for each transfer:
    nft = transfer.nft_address
    if nft in нашей_базе:
      старый_владелец = transfer.old_owner
      if старый_владелец == user.tg_wallet:
        блокируем пользователя
        очищаем доступ
        шлём уведомление в бота
```

### Преимущества перед поллингом:
- Не дёргаем API на каждого юзера
- Событие ловится за 2-3 минуты (практически real-time)
- Не блокчейн-нагрузка — только один запрос на коллекцию
- Неважно сколько юзеров — 10 или 10000, запрос один

### Когда проверяем:
- **При активации** — обязательно (начальная проверка владения)
- **Фоновый крон каждые 2-3 минуты** — ловим transfer-события
- **При подозрении** — если бот получил ошибку от API ключа — ре-чекаем

## 5. CRON (каждые 2-3 минуты)

```
last_lt = load_last_known_lt()  # последняя известная транзакция

transfers = get_nft_transfers(
    collection=EQC_..._RS_k,
    start_lt=last_lt
)

for tx in transfers:
    if tx.nft_address in activated_nfts:
        user = find_user_by_nft(tx.nft_address)
        if tx.new_owner != user.wallet:
            lock_user(user)
            notify_bot(user, "NFT переведён. Доступ закрыт.")
            remove_nft_from_activated(tx.nft_address)

save_last_known_lt(max(transfers.lt))
```

**Один API-запрос** за всё. Неважно 10 или 1000 юзеров.

## 8. БОТ @AgenticsBot

### Команды:
- `/start` — начало, регистрация по токену
- `/menu` — инфо о текущем агенте
- `/agent` — сменить агента (через Mini App)
- `/reset` — сбросить API-ключ

### Логика обработки сообщения:
```
1. Есть ли tg_id в users.json?
   НЕТ → кнопка "Активировать через Mini App"
   ЕСТЬ → пункт 2

2. NFT всё ещё за пользователем?
   (last_check > 1 час назад → проверяем)
   НЕТ → блокируем, "Купи нового агента"
   ЕСТЬ → пункт 3

3. Есть API-ключ?
   НЕТ → кнопка "Ввести API-ключ" → Mini App
   ЕСТЬ → пункт 4

4. Отправляем запрос:
   System prompt агента + история + сообщение
   → DeepSeek (или OpenAI)
   → Ответ пользователю
```
